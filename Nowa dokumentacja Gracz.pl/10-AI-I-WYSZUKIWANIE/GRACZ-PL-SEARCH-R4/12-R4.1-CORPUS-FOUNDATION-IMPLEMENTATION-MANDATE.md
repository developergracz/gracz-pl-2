## 1. Mission

Zaimplementować wyłącznie warstwę **R4.1 Corpus Foundation** dla SEARCH R4, bez uruchamiania płatnego AI, bez semantic provider i bez generative model.

R4.1 ma przygotować kanoniczny, wersjonowany i testowalny korpus treści, na którym później powstanie semantic retrieval.

## 3. In scope

### 3.1. Corpus schema

Zdefiniować stabilny format:

- document,
- chunk,
- game manifest,
- source class,
- canonical priority,
- content hash,
- content version,
- index schema version.

### 3.2. Game manifests

Minimum dla:

- Poker,
- Tysiąc,
- Warcaby,
- Gomoku.

Manifest ma zawierać:

```text
game_id
display_name
aliases
canonical_rules
academy_sources
guide_sources
topics
locale
```

### 3.3. Source classes

Obowiązkowo:

```text
CANONICAL_RULES
ACADEMY_CORE
GUIDE_APPROVED
PORTAL_INFO
SUPPORTING_CONTENT
```

### 3.4. Approved corpus allowlist

Źródła mogą pochodzić wyłącznie z jawnie dozwolonych publicznych treści gracz.pl.

Nie indeksować:

- sekretów,
- logów,
- plików env,
- kodu źródłowego jako wiedzy dla użytkownika,
- prywatnych danych kont,
- treści innych użytkowników.

### 3.5. Deterministic extraction

Builder ma:

- czytać źródła,
- wydzielać logiczne sekcje,
- przypisywać anchor,
- czyścić markup,
- tworzyć deterministic chunk IDs,
- liczyć hash,
- generować manifest indeksu.

### 3.6. Chunking

Preferować:

```text
1 nagłówek
+ powiązane akapity
= 1 logiczny chunk
```

Nie dzielić arbitralnie co N znaków jako jedynej strategii.

### 3.7. Shadow artifact

R4.1 ma wygenerować artifact, np.:

```text
search-r4/corpus/<version>/
  documents.json
  chunks.json
  games.json
  manifest.json
```

Dokładna ścieżka może zostać dobrana do struktury repo, ale musi być jawna i testowalna.

### 3.8. Validation CLI/test

Musi istnieć walidacja:

- duplicate chunk IDs,
- duplicate canonical URLs,
- broken source path,
- missing anchor,
- unknown source class,
- missing game manifest,
- hash mismatch,
- empty chunk,
- disallowed source,
- mixed content versions,
- invalid schema.

### 3.9. Tests

Minimum:

- deterministic rebuild,
- correct source lineage,
- 100% allowed source coverage,
- reject disallowed file,
- anchors for current public game content,
- Polish diacritics preserved,
- text sanitization,
- stable IDs,
- no secrets in generated corpus.

## 4. Out of scope

R4.1 **nie obejmuje**:

- embeddings,
- vector DB,
- semantic similarity,
- reranker,
- model provider,
- OpenAI/Anthropic/Gemini integration,
- AI API key,
- generation,
- prompt engineering,
- Player Context,
- Learning Graph,
- My Trainer,
- deployment,
- Render changes,
- DB migration.

Jeśli implementacja wymaga któregoś z powyższych, status ma być HOLD i eskalacja do Lead.

## 5. Compatibility requirement

Obecna SEARCH R2 MAX nie może zostać usunięta ani funkcjonalnie zdegradowana.

R4.1 może przygotować nowy corpus builder, ale publiczny search ma działać tak jak przed zmianą.

## 6. Security requirements

- zero sekretów w artifact,
- brak wykonywania skryptów z HTML,
- żadnego eval,
- żadnego remote fetch podczas produkcyjnego request path,
- corpus build opiera się na repo-approved sources,
- generated JSON musi być bezpiecznie serializowany,
- builder nie może indeksować przypadkowych plików przez broad recursive wildcard bez allowlisty.

## 7. Suggested implementation shape

To jest sugestia, nie nakaz nazewnictwa:

```text

  corpus/
  manifests/
  schema/
  tooling/
  tests/
```

```text

→ extractor
→ section parser
→ sanitizer
→ chunk builder
→ validator
→ manifest writer
```
